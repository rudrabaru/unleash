# Known tricky spots

Things that have already bitten this project. If a proposed change contradicts one, correct it by pointing here.

1. **Load models once, at import.** faster-whisper (seconds to load) and silero-vad are loaded at module import, never inside a request. Loading per request would blow the speech-plus-phrase latency budget (10 s) and the 120 s token lifetime. faster-whisper also downloads its model from Hugging Face on first use (a hidden network call): bake it into the image for deployment.
2. **silero-vad needs a matching torchaudio.** `pip install silero-vad` into an environment with a CPU torch pulled the newest torchaudio, whose compiled extension did not match (`_torchaudio.pyd` failed to load). `torch` and `torchaudio` are pinned together in `requirements.txt`.
3. **Word matching is not string matching.** Whisper emits tokens like `Apple,`; each recognized word is lowercased and stripped, then compared by edit distance divided by the longer word's length (similarity at least 0.8). Dividing by twice the length (the old metric) floored any two words at 0.5 and passed about 90% of unrelated sentences. Do not tighten to exact equality (accents) and do not loosen the similarity. Regression tests: filler speech, a phrase from another session, 3 of 5, one spoken word reused.
4. **Use `base.en`, plain.** The multilingual `tiny` model heard "lantern" as "Lenton" and "maple" as "Nappal" on a genuine take (3/5, failing). `base.en` plain passes it (4/5). A vocabulary `initial_prompt` was rejected: it made Whisper emit vocabulary words on noise (`zucchini` x6) and tones (`beep` x13). `hotwords` with the full 136-word list errors in faster-whisper 1.2.1. Re-run `tools/phrase_model_comparison.py` and the non-speech probes before changing any of this.
5. **ffmpeg is a subprocess, and exit code 0 proves nothing.** Extraction is forced to 16 kHz mono whatever the browser recorded. A clip cut off after 2 KB extracted "successfully" with 0.4% of its audio, so the extracted duration is compared with the container's.
6. **Browser recording clocks are not trustworthy.** OpenCV reports MediaRecorder `.webm` as 1000 fps and the file has no seek index, so frame times come from PyAV (`app/media/frames.py`) and the lip-sync check uses only `time_seconds`. The extracted WAV also loses the audio track's start offset; `to_container_time` restores it. Never use `frame_index / fps`.
7. **Decode video once.** `load_frames` counts frames by demuxing packets, then decodes a single time. Never `seek(0)` and decode again: without a seek index the seek can land on a later keyframe. A frame without a timestamp is dropped; a time is never invented. Holding 120 full-resolution RGB frames of a 1080p clip is about 750 MB, so dense frames are capped at 1280 px on the long edge (this moved the liveness score by up to 0.02 on the sample clips).
8. **OpenCV 5 ships without the Haar cascade files**, and installing both `opencv-contrib-python` (required by mediapipe) and `opencv-python-headless` overwrites one build's files with the other's. Depend on the contrib build only. The old Haar face crop silently returned the whole frame.
9. **The speech detector and the MediaPipe landmarker are shared mutable instances** (`reset_states()` between calls; one landmarker created lazily). Only one analysis may run at a time; `orchestrator._ANALYSIS_LOCK` enforces it now that analyses run in worker threads.
10. **Detectors are plain functions.** An `async def` with a blocking body freezes the whole server for the length of the analysis (a live probe completed 1 health request in 17.7 s; it completes 21 now).
11. **The lip-sync open threshold assumes a mostly closed mouth.** It is `median + max(0.02, 0.5 * stdev)` of the clip's own series; a test series where the mouth is open most of the time puts the threshold above every real sample. Model a full-length clip (hundreds of frames) with brief open windows.
12. **The sample clips are not browser recordings.** The real-face clips in `tests/fixtures/video` and `eval/clips` are 1080p H.264/AAC phone-style files (one is video-only), 5-6 s long with a start time of 0. Browser recordings are VP8/VP9 + Opus, about 15 s, with no container duration and odd timestamps. Detector scores measured on the sample clips are a smoke check, not a calibration.
