# Known Tricky Spots — Audio Pipeline

Implementation gotchas identified before coding started. If Claude Code proposes something that contradicts one of these, correct it by pointing back to this file.

1. **faster-whisper model loading.** Must be loaded once at server/module startup, stored in a module-level variable, not reloaded per-request. Loading per-request adds seconds of latency to every single submission and will blow the Stage 1–3 latency budget (< 10s) immediately. If Claude writes code that instantiates the model inside the request-handling function, that's a bug — fix it to load at import time instead.

2. **silero-vad Windows import issues.** silero-vad has occasionally had import/build problems on Windows. If this happens, the pre-approved fallback is `webrtcvad`. This substitution does **not** require a team discussion — it's already agreed in the project plan as the sanctioned fallback path. Document which one is actually in use in this file and in code comments if a fallback is triggered.

3. **Word matching is not string matching, and the similarity metric must not be loosened by accident.** The challenge is 5 random words. Stage 2 compares each recognized word to each target with an edit-distance similarity **normalised by 1× the longer word's length** (an earlier 2× normalisation floored any two words at 0.5 and let ~90% of filler sentences pass), after lowercasing and stripping punctuation (Whisper emits `Apple,`). A word counts at similarity ≥ 0.8, each spoken word can satisfy only one target, and 4 of 5 must match. Exact string matching would reject genuine accents, so do not tighten to equality; do not loosen the similarity either. Regression tests: filler speech, a replayed phrase from another session, 3-of-5, one-spoken-word-reused.

3a. **Whisper tiny mishears isolated uncommon words, and a vocabulary hint lowers its confidence.** On a genuine take, "lantern" came out as "Lenton" and "maple" as "Nappal" (3/5, gate failed). Giving it the vocabulary as `initial_prompt` fixes the transcript but drops per-word probabilities (walnut 0.10, maple 0.23) below the 0.5 per-word confidence floor in `match_words_fuzzy`. The multilingual `base` model did not help, but English-only models do: on the same take `base.en` plain scored 4/5 at the existing 0.5 floor and `tiny.en` + prompt scored 5/5 at floor 0.1 (decision D-18, single recording). `hotwords` with the full 136-word vocabulary raises "maximum decoding length must be > 0" in faster-whisper 1.2.1. Direction agreed in decision D-04: vocabulary hint + `condition_on_previous_text=False` + a lower confidence floor, with the final floor chosen from false-accept/false-reject probes. `condition_on_previous_text=False` is needed because the hint otherwise produces repeated trailing words.

4. **Model load time vs. token expiry.** The HMAC challenge token has a 2-minute expiry (see root `CLAUDE.md` and `backend/app/core/security.py`). faster-whisper's first-load delay (15–30 seconds) must never happen inside the request path — it must be fully absorbed at server startup, before any token is ever issued. faster-whisper also **downloads the model from Hugging Face on first use**, which is a hidden runtime network call — in deployment the model must be baked into the image (decision D-20). If Claude sees model loading anywhere near request handling, that's the same class of bug as #1.

5. **ffmpeg is a subprocess, not a library.** Audio extraction from the `.webm` blob must invoke `ffmpeg` as a subprocess call, not use a Python ffmpeg-wrapper package as the actual decode/resample engine. The output WAV must always be forced to exactly 16kHz mono, regardless of what the browser's `MediaRecorder` actually captured — never trust the browser-side sample rate hint.

6. **Browser `.webm` frame rate is not trustworthy.** OpenCV reports MediaRecorder `.webm` as 1000 fps, and `frame_index` in the lip series counts the 30 *subsampled* frames, not native frames, so `frame_index / fps` puts every lip sample near t = 0.03 s and Stage 4 degrades to `None`. The fix (decision log B4/D-19) is a real timestamp per sample read from the container with PyAV (already installed via faster-whisper): `time_seconds` per sampled frame. Until then, never claim Stage 4 produces a real score on browser recordings.

7. **Stage 4's per-session "open" threshold breaks if the sample doesn't look like real speech.** `_av_alignment.py` derives its mouth-open threshold as `median(lip_series) + 0.5*stdev(lip_series)`, which only works when "mouth closed" is the majority class across the sampled clip (true for a real ~15s challenge recording where only a few short words are spoken). A synthetic test that makes "mouth open" the majority (e.g. tolerance-widened word windows covering most of a short series) breaks this: the median itself becomes the open value, and adding a margin pushes the threshold above every real "open" sample, forcing every word to fail alignment. When writing tests or synthetic fixtures for Stage 4, always model a full-length clip (hundreds of frames) with brief open windows, not a short clip dominated by the speaking windows.
